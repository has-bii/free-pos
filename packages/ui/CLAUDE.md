# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

See the root `CLAUDE.md` first for monorepo-wide commands and conventions. This file covers `packages/ui`-specific details.

## What this is

`@repo/ui`: shared shadcn/ui component library, currently consumed by `apps/frontend`. No build step — components are plain `.tsx` source, consumed the same way every other `@repo/*` package is (see root `CLAUDE.md`'s Workspace/versioning conventions section): a consumer's `tsconfig.json` maps `@repo/ui/*` to `../../packages/ui/src/*`, and Vite is given a matching `resolve.alias` since (per that same section) Vite doesn't read tsconfig `paths` on its own.

## Commands

```
pnpm lint            # biome check .
pnpm typecheck       # tsc --noEmit
pnpm test            # no-op — no tests yet
```

Run these from `packages/ui/`, or from the repo root with `pnpm --filter @repo/ui <script>`.

## Structure

- `components.json` — shadcn CLI config for this package: `new-york` style, `neutral` base color, `lucide` icons, CSS variables on. `apps/frontend` has its own `components.json` too (pointing `tailwind.css` back at this package's `globals.css`) — shadcn's monorepo docs require keeping `style`/`iconLibrary`/`baseColor` identical across both files, since the CLI reads whichever `components.json` is closest to the file it's asked to add a component to.
- `src/styles/globals.css` — the Tailwind v4 entry point (CSS-first config, no `tailwind.config.ts`): theme tokens as CSS variables in OKLCH (`:root`/`.dark`), mapped into Tailwind's `@theme inline`. `apps/frontend` imports this file directly rather than having its own copy, so there is exactly one theme definition for the whole app. The `@source` lines exist so Tailwind's class scanner reaches into `apps/frontend` even though this CSS file physically lives in a different package — Tailwind's automatic detection (walking up to the nearest `.git`) likely already covers this, but the explicit paths are cheap insurance.
- `src/lib/utils.ts` — `cn()`: `clsx` + `tailwind-merge`, used by every component to merge a caller's `className` prop with variant classes without Tailwind class conflicts.
- `src/components/ui/*.tsx` — shadcn-generated primitives: `button`, `card`, `alert`, `field` (`Field`/`FieldGroup`/`FieldLabel`/`FieldError`/`FieldSeparator`/etc. — headless, form-library-agnostic, used instead of `form.tsx` which is `react-hook-form`-specific), `input`, `input-group` (wraps an `input` with leading/trailing addons, e.g. a password show/hide button), `label`, `separator`, `textarea` (pulled in as `input-group`'s own dependency, not directly used yet). Each self-imports via `@repo/ui/lib/utils`, matching the self-referencing subpath-import style `apps/auth` already uses for its own modules. Add more from the repo root with `pnpm ui:add <component>` (e.g. `pnpm ui:add badge`) — a root `package.json` script wrapping `pnpm dlx shadcn@latest add --cwd packages/ui`, so it works from anywhere in the repo without `cd`ing first. The CLI writes into `src/components/ui/` based on the `ui` alias in `components.json`. `label`/`separator`/`input-group` pull in `radix-ui` (the newer unified Radix package, pinned in the root catalog) rather than individual `@radix-ui/react-*` packages like `button.tsx`'s `@radix-ui/react-slot` — both styles coexist here, matching whatever the shadcn registry generates per component.

## Conventions specific to this package

- No `main`/`types`/`exports` in `package.json` — consumers import concrete subpaths directly (e.g. `@repo/ui/components/ui/button`), same as `@repo/auth-kit`. shadcn's own official Vite monorepo template uses a package.json `exports` map with wildcard subpaths instead; this repo intentionally sticks with the tsconfig-`paths` convention used everywhere else instead of introducing a second import-resolution mechanism.
- Don't hand-edit variant classes generated by the shadcn CLI beyond what a real design need requires — re-running `shadcn add` on an already-customized component will overwrite local changes.
